# Техническое SEO

Формат находки: **URL → доказательство → последствие → исправление → повторная проверка → P0–P3 / уверенность / трудоёмкость / зависимости / критерий готовности.**

Состояние конкретного сайта (замеры Lighthouse, текущие находки) — в `sites/<имя>/profile.md`.

## 1. Адреса и доступность
- Варианты домена http/https × www/без www: норма — один канонический, остальные 301. Проверка: `scripts/crawl.py` или `curl -I`.
- Редиректы ≤1 перехода; битых внутренних ссылок 0.
- Доступность URL (200) ≠ индексация: смотреть Вебмастер («Страницы в поиске») и GSC («Проверка URL»); `site:` — ориентир, не вывод.

## 2. robots.txt, sitemap, meta robots
- robots.txt: закрыты служебные пути CMS и страница благодарности, `Clean-param` для utm/регион-параметров, строка Sitemap; CSS/JS/картинки не закрывать.
- sitemap.xml: канонические адреса в нужном протоколе, без noindex-страниц. Tilda пересобирает sitemap сама — после смены зеркала проверить протокол в `<loc>`.
- noindex только на странице благодарности и служебных.

## 3. Canonical и дубли
- canonical = адрес страницы в каноническом протоколе (не http при работающем https).
- Параметры utm/region склеиваются Clean-param (Яндекс) и canonical без параметров (Google).
- Почти одинаковые страницы: либо развести содержание под разные намерения, либо canonical на одну.

## 4. Title, Description, заголовки
- Title уникален, запрос в начале, бренд в конце; ~60 символов — ориентир по обрезке в сниппете, не требование.
- Description уникален, с оффером (срок, минимальный заказ, образец — по профилю); ~150–160 символов — ориентир.
- Один H1, согласован с title и содержанием; H2 по блокам.
- Подмены по UTM (ниша, формулировка товара, регион) не должны менять версию без параметров.

## 5. Внутренняя перелинковка
- Коммерческая страница достижима с главной ≤2 кликов, ≥2 входящих ссылок с осмысленным анкором.
- Меню шапки скрывает пункты без соответствующего блока на странице.

## 6. Контент в HTML и после JS
- Основной текст — в HTML (блоки T123 это обеспечивают). Подстановки скриптом — поверх базового текста.
- Квизы и попапы роботам не видны: условия держать в тексте страницы.

## 7. Мобильная версия
- Без горизонтальной прокрутки на 320–390 px, кнопки ≥44 px, формы и попапы работают, телефон — `tel:`. Проверка: эмуляция, скриншоты 320/390/768.

## 8. Изображения
- WebP через оптимизатор Tilda (`/-/resize/Nx/-/format/webp/`), `srcset` + `sizes`; LCP-картинка с `fetchpriority="high"` и preload; остальные `loading="lazy"`; `width/height`; содержательный alt (декоративные — alt="").
- Первое обращение к новой картинке через оптимизатор отдаёт тяжёлый оригинал — «прогреть» варианты.

## 9. Скорость и Core Web Vitals
- Лаборатория (Lighthouse, PageSpeed «Диагностика») и поле (CrUX в PageSpeed, Метрика «Скорость») — разные источники. «CWV пройдены» — только по полевым данным за 28 дней.
- Что обычно помогает: меньше одновременных анимаций на старте, предзагрузка LCP-картинки, один шрифт, отложенные блоки ниже первого экрана, ленивые сторонние виджеты.

## 10. Структурированные данные
- Проверять валидность, соответствие видимому тексту, заполненность полей (не оставлять шаблонных значений вида «[https://ваш-домен/]»).
- По смыслу уместны: LocalBusiness/Organization с адресами и телефонами, Service, BreadcrumbList, FAQPage. Google ограничивает показ FAQ-расширений для коммерческих сайтов — расширенные сниппеты не обещать. Без реальных данных не добавлять AggregateRating, Review, Offer с ценами.
- Валидация: Вебмастер → «Структурированные данные», Google Rich Results Test, validator.schema.org.

## 11. Вёрстка (если аудит включает интерфейс)
- Проверять не только выход за экран и шрифты, но и **пересечения внутри блоков**: текст/текст, текст/картинка, выход за карточку на 320–1920 px; на время замера отключать анимации и `content-visibility`.
- Типографика единая: H1 ≥ H2 на всех ширинах, веса и межстрочные однотипных заголовков совпадают.

## Tilda: куда вносить изменения
| Что | Где |
|---|---|
| Title, Description, og-поля, canonical, индексация | Настройки страницы → SEO / Соцсети |
| Язык сайта, главное зеркало, HTTPS, robots.txt, счётчики | Настройки сайта → Основные / Домен / SEO / Аналитика |
| JSON-LD, preload, `window.YM_ID` | Настройки сайта → Дополнительно → HEAD (или HEAD страницы) |
| Тексты, картинки, кнопки, скрипты подстановки | блоки T123, замена содержимого блока |
Перед заменой блока T123 — копия исходника. После публикации проверять живой адрес, не редактор.
