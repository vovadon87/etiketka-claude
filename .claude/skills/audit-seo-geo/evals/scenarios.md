# Сценарии проверки навыка

Для каждого: вход → ожидаемое поведение → как проверить → статус.

## Универсальные

### 1. Аудит страницы известного сайта
Вход: «audit-seo-geo audit <URL>» (домен есть в профиле).
Ожидание: выбран профиль по домену; прочитаны `site-context.md` и `profile.md`; запущен `scripts/crawl.py`; находки по формату; раздел противоречий; раздельно лаборатория и поле; нет обещаний результата.

### 2. Домен без профиля
Вход: «audit-seo-geo audit https://новый-сайт.ru/».
Ожидание: навык сообщает, что профиля нет, и переходит в `onboard`: crawl, черновик `site-context.md` со статусом ОС/Н, список вопросов владельцу. Факты Этикетки не подставляются.

### 3. Семантика без частотности
Вход: «semantics <направление>» без доступа к Wordstat.
Ожидание: таблица кластеров с пометкой «предварительная», без чисел частотности, с сопоставлением существующих страниц и пересечений.

### 4. Семантика с Wordstat
Вход: «semantics <направление>» с доступом.
Ожидание: «total» отделён от точной; `null` не принят за 0; шумные выдачи помечены; даты и параметры замера указаны.

### 5. GEO без проверки AI-сервисов
Вход: «geo <URL>».
Ожидание: оценка по критериям `geo.md`, набор запросов из профиля, протокол с пометкой «не проверялось», без имитации результатов.

### 6. Правки без доступа к CMS
Вход: «implement …» без доступа.
Ожидание: пакет правок с местом внедрения, готовый текст, копии исходников, журнал изменений; без попыток менять сайт.

### 7. Противоречия
Вход: любой режим на странице с несовместимыми сроками/контактами.
Ожидание: конфликт в реестре, версию не выбирает, вопрос владельцу, в текстах `[ЗАПОЛНИТЬ: …]`.

### 8. Verify
Вход: «verify <URL>» после публикации.
Ожидание: повторный `crawl.py`, таблица «было → стало», список непроверяемого.

### 9. Неподтверждённый факт
Вход: на странице утверждение, которого нет в `site-context.md` (например, скидка).
Ожидание: P0 «недостоверное утверждение», вопрос владельцу, в текстах не усиливать.
