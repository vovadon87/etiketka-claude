# Сценарии проверки навыка

Для каждого: вход → ожидаемое поведение → как проверить → статус (выполнен / описан для запуска).

## 1. Аудит главной страницы
Вход: «etiketka-seo-geo audit https://etiketka.express/».
Ожидание: запуск `scripts/crawl.py`, находки по формату, раздел противоречий (сроки, http-canonical, незаполненный `url` LocalBusiness), раздельно лаборатория/поле, нет обещаний результата.
Статус: **выполнен 2026-10-15** (см. предварительный аудит в итоговом отчёте).

## 2. Оптимизация отраслевой страницы
Вход: «page https://etiketka.express/etiketki-dlya-kosmetiki-parfyumerii».
Ожидание: шаблон page-optimization, материалы только из списка ПВ, срок как противоречие (не выбирать), места внедрения в Tilda.
Статус: выполнен частично 2026-10-15 (проверены title/description/H1/разметка/ссылки; полный пакет текстов — при запуске).

## 3. Семантика без частотности
Вход: «semantics косметика» при отсутствии Wordstat.
Ожидание: таблица кластеров с пометкой «предварительная», без чисел частотности, с сопоставлением существующих страниц и указанием пересечения главной и /naklejki.
Статус: описан для запуска (образец ядра есть в `semantika-kosmetika-direct.xlsx` проекта).

## 4. GEO-аудит без проверки AI-сервисов
Вход: «geo https://etiketka.express/».
Ожидание: оценка по критериям geo.md, набор запросов для ручной проверки, протокол с пометкой «не проверялось», без имитации результатов.
Статус: выполнен частично 2026-10-15 (критерии на странице проверены; запросы в сервисах не проверялись).

## 5. Правки без доступа к CMS
Вход: «implement — исправить canonical, LocalBusiness url, добавить ссылки между страницами» без доступа к Tilda.
Ожидание: пакет правок с указанием места (настройки / HEAD / блок T123), готовый текст, копии исходников, журнал изменений; без попыток менять сайт.
Статус: описан для запуска.

## 6. Противоречивые сроки/контакты
Вход: любой режим на странице, где «от 1 дня» и «1–3 дня» соседствуют.
Ожидание: навык фиксирует конфликт в реестре, не выбирает версию, ставит вопрос владельцу, в текстах использует `[ЗАПОЛНИТЬ: срок]` до решения.
Статус: **выполнен 2026-10-15** — конфликт обнаружен скриптом (см. site-context.md, реестр №1) и внесён без выбора версии.

## 7. Проверка после правок (verify)
Вход: «verify https://etiketka.express/» после публикации.
Ожидание: повторный `crawl.py`, таблица «было → стало» по тем же полям, список непроверяемого.
Статус: описан для запуска.
