# Wordstat: источники, операторы, правила работы с частотностью

## Главное правило

**Частотность Wordstat никогда не выдумывается.** Каждое число в ядре имеет: источник (инструмент/файл), дату замера, регион, тип замера. Число без этих четырёх полей в отчёты не попадает. Если данных нет — статус «нет данных» (ниже порога инструмента ≠ подтверждённый ноль) или «не измерялось».

## Источники (по приоритету)

1. **Выгрузки пользователя** — XLSX/CSV/TXT в рабочей папке (у владельца: `Downloads/Этикетки/Семантика_*`). Формат «эталонной» выгрузки см. ниже. Читать через `scripts/wordstat_io.py`, исходные файлы не изменять.
2. **MCP-инструменты Wordstat** (если подключены в сессии): `wordstat_suggest` (топ запросов + частотность), `wordstat_dynamics` (динамика, работает только оператор `+`), `wordstat_regions` (региональный срез), `wordstat_cluster`, `check_search_volume`. Фиксировать имя инструмента в колонке «Источник».
3. **Существующие файлы ядра** — проверить рабочую папку и `outputs/*/02_WORDSTAT_SEMANTICS.xlsx` прошлых прогонов; данные старше 90 дней помечать как устаревшие.
4. **Яндекс Вебмастер «Запросы»** — фактические показы; **не смешивать с частотностью Wordstat** (разные величины: спрос ≠ показы сайта). В таблицах — отдельные колонки с подписью источника.
5. **Подсказки Яндекса, GSC** — только для расширения списка фраз, не для частотности.

Без доступа ни к одному источнику: собрать список фраз-гипотез, сохранить файл «на дозамер» (шаблон `templates/semantic-core.csv`, частотность пустая), черновик статьи разрешён только с пометкой «семантика предварительная, частотность не подтверждена» в шапке и в отчёте.

Не обходить CAPTCHA, авторизацию и ограничения источников.

## Операторы (сверять с https://yandex.ru/support2/wordstat/ru/content/operators)

| Оператор | Что фиксирует | Пример |
|---|---|---|
| без операторов | широкое соответствие: фраза + любые добавки, словоформы, порядок | `этикетки для косметики` |
| `"фраза"` | только это число слов; словоформы и порядок свободные | `"этикетки для косметики"` |
| `!слово` | точная словоформа; добавки допускаются | `!этикетки !для !косметики` |
| `+слово` | принудительно учитывать стоп-слово/предлог | `этикетки +для косметики` |
| `-слово` | исключить | `наклейки -маникюр` |
| `[фраза]` | фиксированный порядок слов | `[печать этикеток]` |

Не путать замеры: «в кавычках» и «с `!`» — разные уточнения, в ядре — отдельные колонки. В «Динамике» Wordstat работает только `+`.

## Обязательные регионы для etiketka.express

1. Россия (id 225) — всегда.
2. Москва и Московская область.
3. Санкт-Петербург и Ленинградская область.

Другие регионы — при подтверждённом спросе и обслуживании. Регион каждого замера пишется в строке данных, не в шапке файла.

## Расширение семантики

Проходы (до исчерпания, не до заранее выбранного числа фраз): синонимы продукта (этикетки/наклейки/стикеры — владелец подтвердил: один продукт); виды продукции клиента; типы упаковки; материалы; технология и отделка; условия эксплуатации; задачи (малый тираж, срочно, макет, цена); вопросительные; регион. Остановка — когда новые проходы перестают давать связанные запросы; в отчёте фиксировать, что это предел источника, а не полный охват.

## Динамика и сезонность

При доступной истории (wordstat_dynamics, 24 мес.): тренд г/г, сезонные пики, растущие подгруппы, сравнение регионов. Суммарный спрос **не** считается сложением пересекающихся фраз — широкие частотности вложенных фраз пересекаются; в каждой таблице с суммами — оговорка.

## Формат эталонной выгрузки (колонки ядра)
