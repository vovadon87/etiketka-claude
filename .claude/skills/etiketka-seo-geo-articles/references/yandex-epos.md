# ЭПОС Яндекса: проверка статьи по четырём аспектам

Источник методики: справка Вебмастера — https://yandex.ru/support/webmaster/ru/epos (проверять актуальность при обновлении навыка). ЭПОС — рамка оценки качества контента Яндексом: Экспертность, Полезность, Оригинальность, Содержательность. Это критерии оценки, а не чек-лист ранжирования; прохождение не обещает позиций.

Каждая статья проходит проверку по всем четырём аспектам. Результат — таблица в `12_EPOS_QA.md`: аспект → вердикт (проходит / требует доработки) → доказательства (цитаты из статьи) → что исправлено.

## Э — Экспертность

Статья должна опираться на реальные производственные сведения, прослеживаемые до источника (реестр `11_FACT_CHECK.md`).

Для типографии этикеток раскрывать через конкретику:
- материалы и их поведение (плёнка/бумага; влага, масла, холод);
- тип клея и условия нанесения;
- способ печати и отделка (ламинация, soft touch) и что они дают заказчику;
- требования к макету (вылеты, цветовая модель, форматы файлов);
- рулонная намотка: направление, диаметр втулки, под автоматическое нанесение;
- ограничения производства (что нельзя/не имеет смысла печатать).

Проверка: каждое техническое утверждение имеет статус VERIFIED / GENERAL VERIFIED в fact-check; факты компании — только со статусом ПВ/ОС из `etiketka-seo-geo/references/site-context.md`. Утверждение NEEDS VERIFICATION в публикуемый текст не попадает.

## П — Полезность

Каждый раздел решает конкретную задачу читателя. После написания раздела ответить:
1. На какой вопрос пользователя ответил раздел?
2. Какое решение читатель сможет принять после него?
3. Есть ли практический результат (критерий выбора, порядок действий, таблица)?
4. Можно ли сократить без потери информации? Если да — сократить.

Абзац, не проходящий вопросы 1–3, удаляется или переписывается. «Вводные» абзацы без информации — удалять.

## О — Оригинальность

Оригинальность смысловая, не лексическая. Переписанный своими словами текст конкурента оригинальным не считается.

Источники оригинальности:
- производственная экспертиза (подтверждённая);
- сравнения «материал × условие эксплуатации» с выводами;
- типичные ошибки заказчиков и как их избежать;
- критерии выбора, которых нет у конкурентов (по `information-gain.md`);
- подтверждённые примеры задач (параметры: материал, тираж, срок — только со статусом ПВ).

Проверка: сопоставить план статьи с анализом конкурентов (`04_COMPETITOR_ANALYSIS.md`) — в статье должны быть содержательные элементы, отсутствующие у проанализированных конкурентов, и они перечисляются в отчёте.

## С — Содержательность

Максимально полное раскрытие целевого интента при высокой плотности пользы.

- Не наращивать объём ради символов; длина определяется интентом (см. `../SKILL.md`, определение объёма).
- Один смысл — один раздел; не повторять одну мысль под разными заголовками.
- Не смешивать самостоятельные интенты в одной статье без необходимости — для отдельного интента предлагать отдельную страницу (режим cluster).
- Проверка покрытия — Semantic Coverage Matrix (по смыслу, не по точным вхождениям).

## Порядок проверки

1. Прогнать `scripts/quality_checks.py` (повторы, спам-паттерны) — механическая часть.
2. Пройти четыре аспекта вручную с цитатами-доказательствами.
3. Провалы — исправить текст и повторить проверку (не более 3 циклов; дальше — зафиксировать ограничение и вынести вопрос владельцу).
